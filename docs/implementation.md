# Implementation notes

The supplied plan is a reference. This version prioritizes a working native component over a framework, plugin registry, backend, cloud sync, or a large test suite. One esbuild bundle, TypeScript, browser APIs, and a handful of modules are enough.

## Platform findings (2026-10-08)

- [Component scopes](https://bgm.tv/group/topic/345291) use userscript metadata; this bundle matches all pages on the three Bangumi hosts so settings are available everywhere. The subject action itself checks the exact detail route and API subject type. Comparisons run in a native floating `<dialog>` within Bangumi, with no separate rating website.
- [Personalization](https://bgm.tv/group/topic/435098) exposes `chiiLib.ukagaka.addGeneralConfig`. It is optional; the comparison dialog also has settings.
- [Cloud settings](https://bgm.tv/group/topic/435662) load on every page and are deleted on disabling a component. History stays in IndexedDB, one record per numeric user ID, separately on each origin.
- [Official v0 schema](https://github.com/bangumi/api/blob/master/open-api/v0.yaml) allows public collections without a bearer token, offset pagination, and limit at most 50. We import all subject types and keep book (1), anime (2), music (3), game (4), and live action (6) pools separate. Each category needs 50 rated subjects independently; other categories never affect its prior, comparisons, or calibration. Private collections require authorization. Collection status and zero ratings do not count toward eligibility.
- [OAuth](https://github.com/bangumi/api/blob/master/docs-raw/How-to-Auth.md) requires a client secret for the documented code exchange. We do not embed secrets or assume site cookies authorize the API. Public API cookies are not used for authentication. Selected rating updates instead use the existing same-origin signed-in `/update/{id}` collection form and its CSRF-protected action. Only `rating` is replaced; status, tags, comment, privacy and any other existing successful form controls are carried over. A fresh form read verifies the score afterward.
- The live developer version was saved and enabled through the signed-in native editor. Bangumi requires a description, readable unminified code without third-party runtime libraries, and review before public use. API access is declared in the component settings. No remote ratings were changed.
- Native navigation uses absolute profile links. Identity detection handles relative and absolute links on Bangumi's own hosts. Subject metadata comes from the active category navigation, title, and cover in the page; the public API is a fallback. This supports adult games that return 404 from the unauthenticated subject API, without changing API permissions.
- Native content mounts beneath the default rating chart in `#panelInterestWrapper`, using Bangumi theme colors and typography. Signed-in loading, public collection pagination, IndexedDB persistence, JSON text backup/restore and personalization were checked on `bgm.tv`. Version 0.2.0 was also checked while signed in on `bangumi.tv`, including the own-profile entry below `#userStatsContainers`, public import and category comparisons. `chii.in` remains unverified. Data is intentionally isolated per origin.

## Scope

Ship: paginated public imports, 50-rating gate, local comparison history, adaptive references, undo/skip/tie, saved precise estimates, two algorithms, backup/restore, own-profile category refinement and selected batch updates. Native DOM integration is best effort and fails closed when the logged-in navigation identity cannot be detected. Failed imports keep the previous snapshot. Successful imports revalidate eligibility, even when it falls below 50; past comparisons and records remain.

Defer: private collection access, full hierarchical Bayesian inference, learned ordinal thresholds, globally refitting every anchor, and cloud synchronization. These do not justify extra architecture in the first version.

## Scoring

Default: conditional Bradley–Terry MAP, with a Gaussian shrinkage prior. Each reference gets a latent mean from a noisy cumulative-logit rating observation and a weak centered Gaussian prior. Nine fixed ordered cutpoints (spacing 0.8, centered at zero) identify latent location/scale. The ordinal map supplies rated-reference priors; the current category-relative output scale is described below. Cutpoints are deliberately fixed rather than jointly learned. This is not full hierarchical Bayesian inference.

Decisive preferences use logistic likelihoods; ties use a soft quadratic equality penalty. Skips are stored but do not enter inference. The displayed sensitivity range uses conditional Laplace curvature plus a noise floor, not a calibrated credible interval. Elo replays the same raw history sequentially against fixed references and does not report an interval. Model changes preview/recompute local scores only. Original, currently imported, and last published ratings are distinct fields; verified batch updates set the last published and current rating fields while preserving the original.

Reference selection minimizes latent distance, a cheap `p(1-p)` information proxy, and avoids previously seen references. Eight useful comparisons is a session budget, not a claim of convergence; the user can continue. Missing anchors after refresh are ignored as evidence. Concentrated ratings show a warning.

Backup schema 2 adds categories; schema 1 anime-only backups migrate automatically. Imports validate category membership and account ownership, then recompute derived scores. IndexedDB writes check revisions atomically to avoid overwriting changes from another tab.

## Category refinement and batch updates (0.2.0)

A single choice is stored once and used in both directions when both entries have rated priors. The pairwise evidence is a sparse n×n probability matrix evaluated on demand: each cell has left/right/tie/skip counts with symmetric Dirichlet smoothing. Reversing a pair swaps left/right probabilities; contradictory answers and cycles are retained, with no partial-order constraint. These empirical pair probabilities do not have to be transitive. Scalar BT/Elo ratings summarize the noisy evidence; they cannot reproduce every cell of an arbitrary matrix. Skips never contribute to score inference.

The category scheduler first visits entries with fewer attempts, aims for three useful comparisons per entry, and prefers nearby references that still need evidence. Later rounds can reconsider pairs. Saved history allows resuming after closing the window. Review includes supported recommendations whose rounded score differs from the latest imported rating, plus first scores for unscored public collections. All/none and per-entry selection are available; writing requires an in-dialog confirmation.

Batch writes are sequential with a one-second pause. Every item checks the signed-in account, local revision and fresh remote score before updating; an already-achieved score is treated as confirmed. Conflicts, missing or changed forms, rate limits and unconfirmed writes stop the batch. Verified successes are saved individually and removed from the remaining list. Recommendations stay frozen during the batch to avoid changing the requested scores as reference ratings are updated. Closing or pressing Escape during publishing requests a stop after the current item. Private collections remain outside the import scope.

`tests/profile-preview.html` uses disposable mock collections and blocks actual network requests. Browser checks covered full 50-entry comparison coverage, category counts, selection controls, confirmation, a successful two-item batch, partial failure, score conflict, changed-account rejection, and a server response that did not save the requested score. Mock writes assert preservation of non-rating fields. Light and dark palettes were checked visually. Native checks verified own-profile placement, no entry on another profile, public import, comparison cards, category gate and skip/undo. The native collection form was inspected read-only, including an adult game; no real rating was changed during testing.

Version 0.2.1 stores unscored collection metadata separately from rated anchors. Existing schema-2 data and backups default to an empty unscored list. Unscored targets compare against rated references, never against a fabricated zero-rating prior. The 50-rated-anchor category gate stays unchanged. At least three useful comparisons are required before reviewing a first score. Verified publication promotes the entry to the rated pool, retains its null original rating and preserves the native collection fields. Both models, legacy backups, the gate and first-score suggestions passed core tests; a two-entry first-score mock batch and native public import were checked in the browser.

Version 0.2.2 requests collection status `type=2` and also filters each returned row. Both rated references and unscored targets must be completed. Single-subject comparison requires membership in the imported completed pool. Imports without the completed-only marker lose their cached collections and import timestamp, preserving raw comparison history and records until refresh. Publication rechecks the native form's completed status before treating a score as confirmed or posting an update. Pagination tests cover all four excluded statuses, and browser mocks verify status-change rejection without a write.

## Rankings and score spread (0.3.0)

The own-profile ranking entry opens the existing floating dialog. Completed subjects with at least three useful comparisons are sorted by full-precision refined score within their category; ties share a rank and unsupported subjects remain unranked at the bottom. Category eligibility is unchanged. The score-spread control uses factors 1, 1.5, 2 (default) and 3. It scales latent strengths around the category mean before applying the ordinal score map, preserving the preference order and 1–10 bounds. This is a presentation scale for suggestions, not additional evidence or a claim of improved confidence. It does not force a uniform distribution or separate genuinely tied preferences. Probabilities, rounded recommendations and sensitivity endpoints use the same expanded map; empirical pair probabilities and comparison history are unchanged. Existing backups default to spread 2, and records are recomputed on opening a scoring window. Changing algorithms keeps the selected spread. Publication still requires selection and confirmation.

Core checks cover both models, wider score ranges, ordering, ties, category separation, unsupported entries, probability/score consistency and backup compatibility. Browser mocks verify ranking/category controls and spread persistence; real rating writes are not performed.

## Continuous refinement (0.3.1)

The default category comparison mode pauses after 20 choices, including skips. Every choice is persisted immediately; stopping, reviewing early or closing the window never requires completing a category-wide quota. Reopening starts a short session using the same saved comparison history. Undo removes the event from the current session count. Another session can start immediately; full-pool coverage remains a separate optional mode.

The continuous scheduler computes current estimates once per subject and scores candidate same-category pairs with (1 + local cluster density) × exp(-0.5 × (score gap / 0.75)²) / (1 + prior pair count). Local density is the smaller endpoint neighbor count within 0.75 score points, divided by pool size, favoring dense clusters over isolated equal-score pairs. It skips the last 20 pairs, preserves raw contradictory answers, and permits older pairs to be reconsidered. Unscored entries can be targets but references must be scored. This is a simple close-score heuristic, not an optimal information-gain guarantee; it prioritizes clustered scores without forcing every subject to acquire the same number of comparisons. A 300-entry core check verifies short-session usefulness, close-score selection, saved-history resume, category isolation and continued refinement after full coverage. Browser checks verify pause/continue, undo and early review.

## Rare high scores (0.3.2)

Completed category subjects are calibrated by midpoint percentile of their inferred latent preference. Equal strengths share a percentile, including an entirely tied pool. Piecewise linear knots are (0,4), (0.1,6−spread/2), (0.5,6), (0.9,6+spread/2), (0.975,8.5), (1,9). Thus integer 9 occupies about 2.5% of a sufficiently differentiated pool; ties and finite pool size make these targets approximate. Automatic suggestions range from 4 to 9; a 10 is only chosen manually by the user on Bangumi. Existing imported 10s remain valid reference ratings and are never automatically changed. Spread changes the middle band while keeping both rare-score thresholds fixed. This replaces the 0.3.0 output map; imported ratings may still range 1–10.

Batch estimates share the category distribution, and each choice/undo recomputes all existing suggestions so ranking and review agree. Existing histories and backups remain usable. The stored ten-element weights now interpolate adjacent integer scores and must not be interpreted as posterior confidence; empirical four-outcome pair probabilities are unchanged. Sensitivity endpoints use the same percentile map. The scale is relative to the completed category pool and can move when the pool changes. Focused checks cover both models, floor, tail targets, tied clusters, spread, and backup compatibility.

## Manual ranking (0.3.3)

The ranking table supports pointer/touch dragging with edge scrolling and keyboard Arrow Up/Down/Home/End. Changes preview an exact category order before saving; cancel restores the saved state. A saved order takes precedence over the model, generates local 4–9 suggestions from positional midpoint percentiles, and remains stable across reloads, model changes and later comparisons. It does not fabricate comparisons or require three observations for a manually ordered subject. Users explicitly save the entire completed-category order, including previously unscored or unsupported subjects. Publication still requires the existing selected batch confirmation. Restoring model ranking removes the category override while preserving every comparison.

Manual orders are optional schema-2 data, validated for category and unique IDs and included in backups. Imports filter missing subjects at estimation time; newly imported subjects retain model estimates until included in a new saved order. The category's 50-rated-completed-reference gate remains. Manual scores have no model sensitivity interval. A focused check covers exact order, both algorithms, category isolation, unscored suggestions, restoration and backup compatibility. Mock browser checks verify pointer dragging, keyboard moves, preview cancellation, save/reload and matching review scores.

## Manual order with active models (0.3.4)

Saved order now controls display only; every score remains a BT/Elo estimate, with the three-useful-observation gate and BT sensitivity range restored. Moving entries records decisive comparisons for pairs whose relative order changed between the original displayed list and the saved draft. Unchanged relations and canceled drafts add no evidence. Contradictory older choices remain intact. Later comparisons, spread changes and imports update scores while preserving the saved sequence; new entries append after previously ordered entries. Display order may differ from score order. The model-view toggle preserves the saved order, unlike the former restore action. Existing manual-order backups remain usable and derived positional scores are recomputed with the model when opened. The 0.3.3 positional override is superseded. Focused checks verify both models continue learning, exact display persistence, crossed-pair evidence, unscored suggestions, unchanged-order saves and view switching.
